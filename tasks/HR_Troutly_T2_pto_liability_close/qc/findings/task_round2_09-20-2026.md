## Major issues

### [P0] No Stacked Criteria (Atomicity)

The verifier field in `mcp/verifiers.json` stacks independent requirements in three places.
Criterion 3 requires separate decimal precision for hours, rates, and dollars plus row-total
reconciliation, while criteria 25 and 26 each require correctness for 50 distinct employee
records in a single criterion. Split criterion 3 into formatting and reconciliation checks, and
replace criteria 25 and 26 with independently gradable employee-level checks (or appropriately
scoped groups).

Finding #1, MINOR. Criterion 3 combines formatting and reconciliation checks. Criterion 3
requires independent precision checks for hours, hourly rates, and dollars, then also requires
the total to equal the rows. These can succeed or fail independently, so they should be
separated into formatting and reconciliation criteria.

Finding #2, MAJOR. Criterion 25 collapses 50 PTO-policy facts. Criterion 25 requires the correct
PTO policy for each of 50 named-in-scope employee records in one five-point check. Each employee
policy can be correct or incorrect separately, preventing independent grading; split the check
by employee or into smaller coherent groups.

Finding #3, MAJOR. Criterion 26 collapses 50 PTO-balance facts. Criterion 26 requires 50
separate PTO balances to match the schedule in a single five-point check. Because every employee
balance is an independently verifiable value, this bundled requirement cannot be scored
atomically.

### [P0] Prompt-Rubric Alignment

The request PDF explicitly requires "employee ID, name, department, annual PTO tier in hours" on
the one table and later says "An employee ID on every row," but the relevant row-content
verifier checks only "a name and a department on every employee row"; no verifier requires
employee IDs or annual PTO tiers for every row. It also requires "Dates MM/DD/YYYY," yet none of
the 28 verifier criteria checks date presentation, and it says "Change nothing in Greenhouse,"
yet no criterion checks that Greenhouse remains unchanged. Add verifiers for the missing per-row
columns, MM/DD/YYYY date formatting, and the Greenhouse no-change constraint.

Finding #1, MAJOR. Required employee IDs and annual PTO tiers are not fully graded. The request
PDF requires "employee ID" and "annual PTO tier in hours" in every employee row, and separately
repeats "An employee ID on every row." The row-content verifier checks only "a name and a
department on every employee row," while the two tier verifiers test isolated employees; add
criteria requiring both fields on every row.

Finding #2, MINOR. Required date format is not graded. The request PDF's Form section states
"Dates MM/DD/YYYY," but none of the 28 verifier criteria checks date presentation. Add a
page-format criterion requiring all dates displayed on the PTO liability page to use MM/DD/YYYY.

Finding #3, MAJOR. Greenhouse no-change prohibition is not graded. The Out of scope section says
"Change nothing in Greenhouse," but no verifier inspects or protects Greenhouse data. Add a
state-preservation verifier for the Greenhouse tables so unrelated edits cannot receive a
passing score.
